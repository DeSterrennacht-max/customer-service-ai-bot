## 运行环境与消息可靠性更新

本版本修复生产环境识别、人工接管、消息去重、知识风险判断和登录会话撤销，并将 Telegram 收发处理改为持久化异步队列。

### 运行环境

- Python：3.12.13 → 3.12.14
- Node.js：22.22.2 → 22.23.2
- Next.js：15.5.15 → 15.5.25
- PostgreSQL：16.13 → 16.15
- Redis：7.4.8 → 7.4.11
- 容器 nginx：1.27.5 → 1.30.5
- 修补前端 PostCSS、nanoid、sharp 依赖；锁定 API/Worker 生产依赖版本。

### 功能与修复

1. 正确读取 `APP_ENV=production`，启动时校验生产配置。
2. Docker 构建排除环境文件、私钥及 Git 元数据，缩小应用复制范围；前端容器不再注入后端生产环境文件。
3. 后台手动接管通知客服群，Business 模式接管期间停止自动回复，Beat 每五分钟检查并释放超过八小时的接管会话。
4. 群消息去重同时限定机器人、群 ID 和消息 ID。
5. FAQ/知识页风险等级参与回复决策；高风险普通会话转人工，Business 模式保持静默。
6. Webhook 先持久化再确认接收，独立 Dispatcher/Worker 处理收件与发送；支持限流重试、故障恢复、分段状态及会话详情手动补发。
7. 改密/重置密码撤销全部会话，刷新令牌轮换，退出撤销当前会话；增加登录限速和服务器端超级管理员恢复命令。
8. 禁止直接修改已有机器人的租户，避免关联数据归属不一致。
9. 将“先发布 GitHub 代码、标签和正式 Release，再部署 VPS”写入项目规则与部署流程。

- 线上 HTTPS、登录、令牌轮换与撤销、Worker 和周期调度验证通过。

### 升级与使用说明

- 数据库迁移目标：`20260922_0011`。先备份，再迁移，最后启动应用与单实例 Beat。
- 本版本启用会话记录；旧登录令牌失效，需要重新登录，账号密码保持原值。
- Telegram 超时可能发生在对方已经接收消息之后。此类状态标记为 `uncertain`，需核实聊天记录后手动补发；已发送成功的部分保留回执。
- Python 第三方库保持既有生产版本，其既有安全公告需单独处理。
- 新迁移保留已接收消息和会话撤销记录；上线后不可直接无条件回退旧应用，应先评估数据兼容性。
